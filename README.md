# 机票价格监控 · PVG → GRU（卡塔尔航空 / 多哈中转）

监控上海浦东 → 圣保罗瓜鲁柳斯、卡塔尔航空经多哈中转的往返最低价。  
去返程间隔 3/4/5 天，共 **111 个日期组合**。

**时间窗口会自动滚动**：起点 = 今天 + 10 天，往后共 38 天，返程最晚 = 最晚出发日 + 3 天。  
今天 2026-10-22 打开 → `11-01 ~ 12-08`；明天打开 → `11-02 ~ 12-09`，每天自动往后推。

## 一·五、网页控制台（`启动面板.bat`）

双击后浏览器自动打开 `http://127.0.0.1:5001/`，一个页面里搞定：

- **代理状态条**：实时显示 `http://127.0.0.1:6696` 通不通 —— 抓不到价先看这里，最省事
- **三个按钮**：一键扫描（111 组合）/ 快速扫描（约 59 组合）/ 打开最新报告；扫描中自动置灰，避免两个进程抢数据库
- **四张指标卡**：当前最低、同程最低、历史最低、库内报价 —— 不开扫描也能看，数据直读 `flights.db`
- **进度条 + 实时日志**：每个组合的价格边抓边滚，`68/111` 随时可见
- **价格趋势**：近 12 次扫描的最低价折线（报告里没有的能力）

关掉那个黑窗口 = 停止服务；页面上的「停止服务」按钮效果相同。旧的 bat 全部保留，随时可以退回去单用。

端口被占用会自动往后找空位（5001→5002…），控制台窗口里会打印实际地址。

同程的最低价没进数据库，面板是从扫描输出里现场解析并缓存在 `data/ota_cache.json`，所以**首次打开显示「—」是正常的，跑一次扫描后就有**。

## 二、改日期窗口

`config.yaml`：

```yaml
window:
  mode: relative        # relative = 按今天滚动；fixed = 用写死的日期
  offset_days: 10       # 起点 = 今天 + 10 天
  span_days: 38         # 出发日共 38 天
  tail_days: 3          # 返程最晚 = 最晚出发日 + 3 天
  gap_days: [3, 4, 5]   # 间隔天数，想加 2 天就写 [2, 3, 4, 5]
```

想锁死某段日期，把 `mode` 改成 `fixed`，再填下面的 `start` / `latest_departure` / `max_return`。

## 四、邮件通知

**当前用的是 Resend 通道**（`mail.channel: resend`），已经实测发送成功。收件地址 `你的邮箱@qq.com`。

**什么时候会发：**

- 出现历史新低
- 某组合比上次跌超 8%
- 全局最低价比上次跌超 5%
- 同一组合 12 小时内不重复发

**为什么不用 QQ 邮箱直发（SMTP）？** 你的梯子节点封了 465/587/25 三个邮件端口，`smtp.qq.com` 还被解析成 fake-IP `198.18.0.x`。授权码本身是对的，是端口出不去。Resend 走 HTTPS 443，不受影响。

### 两条通道怎么切

| | Resend（当前） | SMTP 直发 |
|---|---|---|
| 走什么端口 | HTTPS 443，梯子封不掉 | 465/587/25，被节点封 |
| 成本 | 免费 3000 封/月 | 免费 |
| 需要什么 | `resend_api_key`（已填） | QQ 授权码（已填） |
| 发件人 | 固定 `onboarding@resend.dev` | `你的邮箱@qq.com` |
| 收件人限制 | 未验证域名时只能发给注册邮箱本身 | 无限制 |
| 状态 | ✅ 已测通 | ❌ 端口被封 |

**注意 Resend 的两个细节：**

1. **Key 是「仅发送」权限**，所以调 `GET /domains` 会返回 401 `restricted_api_key`——这是正常的，不是 Key 错了。诊断工具已经识别这种情况。
2. **未验证自有域名**时，`from` 只能用 `onboarding@resend.dev`、`to` 只能是注册邮箱。你现在收发都是 `你的邮箱@qq.com`，完全没影响。以后想发给别人，得在 Resend 后台验证域名。

**发不出去怎么办？** 双击 `检测邮件配置.bat` 看卡在哪一步；想真发一封测试邮件就双击 `测试发信.bat`。

## 五、真浏览器核价（`--verify`）

日常扫描只拿 Google 的价。想看携程/同程/飞猪的**实际能下单的价**，就加 `--verify`：程序会起一个真实 Chromium 打开对应搜索页，等价格渲染出来再扫一遍，同时截图存证。

### 什么时候会跑

| 触发方式 | 说明 |
| --- | --- |
| 双击 `核价测试.bat` | 扫描 + 强制核价，浏览器窗口会显示出来 |
| `run.py --verify` | 同上，但不显示浏览器窗口 |
| 自动（`verify.auto: true`） | 最低价低于 `trigger_below`（默认 9900）且距上次核价超过 30 分钟时自动跑 |

**为什么有限流：** OTA 的反爬是**按 IP 计数**的。实测连跑几次后 `www.trip.com` 就开始返 `HTTP 432 whaleguard block`，换全新浏览器指纹、换有界面模式、换真实版本号 UA 都绕不过（同一时刻用 curl 反而能拿到 200，说明它专门拦"浏览器"这类流量）。所以默认 30 分钟内只核一次；被封了给出提示，等几十分钟自动恢复。

**说句实话：携程核价成功率大概一半。** 实测 16:22 成功取到了真实价格，16:41 起就持续被封。它属于"能用但不能依赖"的能力——被拦时报告会明确写"被反爬拦截"，不会给你一个假数字。真要下单前核价，点报告里的链接手动看最稳。

### 第一次用之前

双击 **`登录各大平台.bat`**，浏览器会依次打开携程/同程/飞猪的登录页，你用手机号+验证码登录，按回车进入下一家。登录态存在 `data/browser_profile/`，长期复用，只需做一次。

不登录也能跑（游客公开价），登录后能看到会员价、也更不容易被判定为机器人。

### 核价结果的可靠性

- **只认卡塔尔航空**：程序只在「Qatar / 卡塔尔」出现在同一容器里时取那个价，不会拿别家航司的低价冒充。
- **被拦会写清楚**：是 IP 被封、人机验证、还是该页没库存，报告里逐条标注，不假装成功。
- **截图一起存**：`reports/verify_时间_平台.png`，报告里内嵌，邮件里不带（避免被当垃圾邮件）。

| 平台 | 日常扫描 | 加 `--verify` 核价 |
| --- | --- | --- |
| **Google Flights** | ✅ 自动抓，单次 0.7 秒，无配额 | — |
| **同程旅行** | ✅ **自动抓（全航司最低价，免登录）** | —（改由 `cn_ota` 抓，见下） |
| **携程国际** | ❌ 只给链接 | ⚠️ Akamai `whaleguard` 按 IP 拦（HTTP 432），时灵时不灵 |
| **飞猪** | ❌ 只给链接 | ⚠️ mtop 需 UMID 设备指纹，且搜索页要求登录 |
| **天巡** | ❌ 只给链接 | ⚠️ PerimeterX 验证码，基本必拦 |

### 同程是怎么抓到的（重要）

这里以前写过「同程该页无国际航线库存」，**那是错的**。真实原因是查错了产品线：

| 产品 | 入口 | 结果 |
| --- | --- | --- |
| 国内机票 | `/flights/itinerary/roundtrip/` | 用 PVG/GRU 查国际航线，永远返回「没有对应航班」 |
| 国际机票 | `/iflight/` | 正确入口，有 上海→圣保罗 全航线 |

国际站的链路：

1. 打开 `https://www.ly.com/iflight/`，页面风控 SDK 会给 `/miflightapi/*` 自动加一个
   `user-dun` 头（约 650 字符的会话令牌）
2. 抓到这个令牌后，**纯 HTTP 就能调价格日历接口**，不再需要浏览器
3. `GET /miflightapi/ts/calendar?D=SHA&A=GRU&DD=..&BD=..&ED=..`
4. 往返列表页 `/iflight/book1.html` 要登录（跳 passport + 拼图），
   所以往返价用「去程日历 + 返程日历」合成

**一个坑必须记住**：日历里每个日期给两个数，`P` 是基础票价（税前），`TP` 才是含税总价。
11/19 是 `P=2435 / TP=5699`，用 P 会把价格低估近一半。代码里已强制取 `TP`。

**城市码也不同**：同程国际站用 `SHA` / `SAO`，不是机场码 `PVG` / `GRU`。

**代价**：拿到的是**全航司**最低价，不限卡塔尔航空。要看 QR 专用的价，还是以 Google 那栏为准。

**一个必须知道的实测结论：** 携程上 11/17→11/20 的**全页最低价 ¥10,387 是埃塞俄比亚航空**，卡塔尔航空要 **¥12,088**。所以 `--verify` 内置了航司关键词过滤，只取和「Qatar / 卡塔尔」出现在同一容器里的价格，否则会拿别家航司的价骗你。

**另一个更要紧的：** 携程实测卡塔尔航空 ¥12,088，而 Google 报的是 ¥9,485，差 ¥2,600。这种差距就是必须核价的理由——下单前一定以携程/航司官网的实际可订价为准。

### 「只给跳转链接」是什么意思

不是"登录才能看价"，也不是"要收费"。报告里那些按钮点开，就是对应平台**已经带好航线、日期、往返参数**的搜索页，价格由平台自己实时显示，你正常看就行。

脚本抓不到的是**价格本身**，原因全是反爬，跟账号无关：

| 平台 | 真实拦截机制 | 能否绕过 |
|---|---|---|
| 天巡 | PerimeterX 人机验证（`captcha-v2`） | ❌ |
| 携程 | **Akamai Bot Manager**：返回 1885 字节的 `Challenge Validation` 页 + `sec_cpt` cookie，要 JS 算 sensor data 换 `_abck` | ⚠️ 看 IP 声誉，时通时不通 |
| 飞猪 | 淘宝 mtop 网关签名 `md5(token&t&appKey&data)` + `bx-umidtoken` 阿里 UMID 设备指纹 | ❌ 签名可算，指纹不可伪造 |
| 同程 | 国际站要 `user-dun` 会话令牌；国内站接口零签名 | ✅ 已实现 |

**注意：HTTP 200 不等于成功。** curl 打携程的搜索页会返回 200，但正文是 1885 字节的挑战页，
必须看正文特征才能判断到底拿到数据没有。

**登录有用吗？** 一半有用。登录能拿到会员价、能看到更低的代理舱位，但脚本要抓价仍然得绕过签名。
真正能落地的做法是 Playwright 起一个真浏览器、挂上你的登录态去读页面。

代价：装 300MB Chromium 内核、每次比 API 慢 3 倍、天巡仍可能弹验证。所以携程/飞猪默认只给链接，
同程因为接口够干净，已经做成免浏览器的正式数据源。

## 八、常见问题

**价格全是「失败」？**  
梯子没开，或开了但没走全局/TUN。先在浏览器打开 `google.com` 确认能访问。

**想改舱位？**  
`route.cabin` 改成 `business` 看商务舱，`premium-economy` 是超级经济舱。

**数据库能删吗？**  
`data/flights.db` 删了会丢失历史价，"历史新低"判断要从头积累。想重置就删它。

**11/01 出发怎么要 ¥30,025？**  
真实价。临近日期 + 周末，QR 低价舱位已售罄。11/17~11/25 才是低谷（¥9,485 起）。
